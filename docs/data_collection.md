# Toy2Box 데이터 수집 기록

## 과업과 저장 형식

Agibot 오른팔로 테이블의 트럭 장난감을 집어 박스 안에 놓는다. 액션은 상대 이동 3축, 회전 3축, 그리퍼 개폐의 7차원이다. 관측에는 관절, 손끝, 트럭, 박스 등의 상태가 저장된다. 카메라 RGB 프레임은 원본 HDF5에 저장하지 않았다. 영상은 시뮬레이터 재생으로 별도 생성했다.

수집기는 성공 원본 시범에서 파지 변환을 참고하고 현재 상태에 따라 `settle → approach → descend → close → lift → transfer → lower → release → retreat → wait` 단계를 진행한다. 실제 저장은 기존 성공 조건을 연속으로 충족할 때 이뤄지므로 성공이 확인된 시점에 시범이 종료될 수 있다.

핵심 구현은 다음과 같다.

- 트럭 바닥이 박스 상단보다 충분히 높아진 다음 수평으로 운반한다.
- 트럭의 박스 입구 정렬과 높이를 확인하고 그리퍼를 연다.
- 성공한 시범을 HDF5에 저장한다. 성공·실패 후 모두 장면과 기록 버퍼를 리셋한다.
- 성공 횟수와 실패 이유, 단계 변화, 최종 상태, 리셋 완료 여부를 실행 JSON에 기록한다.
- 수집 방식은 실행 로그의 `mode`로 구분한다. 이 문서의 주요 두 원본은 모두 자동 수집이다.

## 주요 원본 비교

| 항목 | 표준 자동 100개 | 최근 변화형 자동 20개 |
|---|---:|---:|
| 파일 | `toy2box_agibot_auto_100.hdf5` | `toy2box_agibot_idle21_n20.hdf5` |
| 저장 성공 수 / 총 시도 | 100 / 278 | 20 / 120 |
| 저장 프레임 | 29,229 | 8,406 |
| 저장된 시범의 총 시간 | 1,461.45초 | 420.30초 |
| 평균 길이 | 14.6145초 | 21.015초 |
| episode별 idle 평균 | 0.6969% | 19.7918% |
| episode별 idle 최소~최대 | 0.4988~0.8511% | 18.4758~20.8925% |
| 전체 프레임 가중 idle | 0.6843% | 19.8073% |
| 그리퍼 전환 | 모두 2회 | 모두 2회 |
| 리셋 완료 기록 | 278회 | 120회 |
| seed | 42 | 101 |

`idle = mean(all(actions[:, :6] == 0, axis=1))`이다. 매우 작은 비0 명령은 idle에 포함되지 않는다. 그리퍼 전환 2회는 닫기·열기에 대응하지만, 그 자체로 성공을 증명하지는 않는다.

## 최근 20개에 추가한 동작 변화

- 부드러운 속도 변화: 기본 설정에서 기존 명령 크기의 약 45~100%.
- 접근·운반 중 작은 중간 위치 보정: 최대 8 mm 설정, 마지막 4 cm에서 추가 위치 보정 제거.
- 접근 중 작은 회전 보정: 최대 0.025 rad 설정.
- 목표 idle 비율: 21%, 시도별 작은 무작위 변화 적용.
- 누적된 실제 idle 프레임을 보고 이동 중 약 0.25~0.65초의 멈춤을 분산한다.
- 멈춤 중 개폐 명령을 유지하며, 의도적인 멈춤은 단계 진행·정체 감시 시간에서 제외한다. 전체 episode 시간은 계속 흐른다.

위 값은 수집 로그와 수집기 설정에 근거한다. 속도 변화와 멈춤이 추가된 자동 생성 시범이며, 직접 키보드로 조작한 사람 시범으로 분류하지 않는다.

## 전체 시도에서 나타난 실패

| 실패 이유 | 표준 자동 100개 수집 | 최근 20개 수집 |
|---|---:|---:|
| approach 정체 | 119 | 91 |
| descend 정체 | 37 | 6 |
| lift 정체 | 4 | 2 |
| transfer 정체 | 7 | 0 |
| 트럭을 함께 들어 올리지 못함 | 2 | 1 |
| 릴리즈 전 박스 입구를 벗어남 | 5 | 0 |
| wait 시간 초과 | 4 | 0 |
| 성공 | 100 | 20 |

이는 수집기의 중단 이유이며 BC 정책 실패 진단과 동일하지 않다. seed와 제어 방식이 다르므로 두 열의 차이를 특정 요인의 인과 효과로 단정하지 않는다.

## 함께 보관한 파일과 실제 개수

| 파일 | 실제 episode 수 | 의미 |
|---|---:|---|
| `toy2box_agibot_auto_100.hdf5` | 100 | 주요 원본, 표준 자동 수집 |
| `toy2box_agibot_idle21_n20.hdf5` | 20 | 주요 원본, 최신 idle 목표 21% 자동 수집 |
| `toy2box_agibot_auto_n20.hdf5` | 20 | 이전 변화형 자동 수집, idle 평균 4.78% |
| `toy2box_agibot_annotated_100.hdf5` | 99 | 100개 원본에서 annotation한 파일 |
| `toy2box_agibot_n20_annotated.hdf5` | 20 | 이전 20개 원본에서 annotation한 파일 |
| `toy2box_agibot_mimic_n100_500.hdf5` | 500 | 100개 계열의 Mimic 성공 생성 시범 |
| `toy2box_agibot_mimic_n20_500.hdf5` | 499 | 이전 20개 계열의 Mimic 성공 생성 시범 |

파일명에 포함된 수보다 실제 HDF5의 episode와 프레임 수를 우선한다. 파일명 `500`은 이 문서에서 생성 성공률의 분모로 사용하지 않는다. 실패 생성 `_failed.hdf5` 파일은 이 Release에 포함하지 않았다.

## 버전 연결 확인

action 배열과 `obs/eef_pos` 배열을 float32로 변환한 바이트의 SHA256을 비교했다.

- 100개 annotation의 99개는 원본과 일치한다. 원본 `demo_39`는 annotation에 없다. 제외 이유는 별도 로그로 확인되지 않았다.
- 20개 annotation은 이전 `auto_n20`의 20개 모두와 일치한다.
- 동일 annotation은 최신 `idle21_n20`과 일치하는 episode가 없다.
- 생성 파일은 기존 annotation 파이프라인 및 학습 설정과 함께 보관했다. 생성 경로를 원본과 동일 배열로 직접 비교할 수는 없다.

최신 20개에서 annotation·Mimic을 다시 실행했다는 기록은 현재 없다. 기존 `mimic_n20_500`을 최신 idle 21% 시범의 증강 결과라고 설명하지 않는다.
